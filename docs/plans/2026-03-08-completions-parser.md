# Plan: Parse Forge/Cast Zsh Completions into Structured TypeScript

## Context

Crucible wraps `forge` and `cast` CLIs but currently only plans to expose a handful of hardcoded flags. Running `forge completions zsh` outputs a ~312KB zsh completion script with every flag, subcommand, and argument in a highly regular format (generated by Rust's `clap` crate). We want to parse this into typed TypeScript registries that Crucible can import — giving us a complete catalog of CLI options with descriptions, value types, and enum choices.

The project is pre-implementation (no `src/` files yet), so we're creating these files fresh.

## Files to Create

| File | Purpose |
|------|---------|
| `src/lib/completionTypes.ts` | Shared types: `CliOption`, `SubcommandDef`, `CliCompletionRegistry` |
| `scripts/generate-completions.ts` | Standalone Bun script that parses zsh completions → TypeScript |
| `src/lib/forgeCompletions.ts` | **Generated** — typed registry for all forge subcommands/options |
| `src/lib/castCompletions.ts` | **Generated** — typed registry for all cast subcommands/options |

## Step 1: Define Types (`src/lib/completionTypes.ts`)

```typescript
export interface CliOption {
  name: string;              // "--broadcast", "--fork-url"
  short?: string;            // "-f"
  aliases?: string[];        // ["--rpc-url"] for --fork-url
  description: string;
  valueType: "boolean" | "string" | "path" | "dir" | "enum";
  valueName?: string;        // Label like "THREADS", "URL"
  enumValues?: { value: string; description: string }[];
  repeatable: boolean;
  conflictsWith?: string[];
}

export interface SubcommandDef {
  name: string;
  description: string;
  aliases: string[];
  options: CliOption[];
  subcommands: SubcommandDef[];  // nested (e.g., cache -> clean, ls)
}

export interface CliCompletionRegistry {
  tool: "forge" | "cast";
  globalOptions: CliOption[];
  subcommands: SubcommandDef[];
}
```

## Step 2: Build Parser Script (`scripts/generate-completions.ts`)

Runs `forge completions zsh` and `cast completions zsh` via Bun shell, then parses in 3 passes:

**Pass 1 — Extract subcommand tree:** Parse `_forge_commands()` / `_forge__cache_commands()` functions at bottom of file. Each has lines like `'test:Run the project'\''s tests'`. Group aliases by matching descriptions. Function name nesting (`__cache__clean`) maps to subcommand hierarchy.

**Pass 2 — Extract flags per subcommand:** Walk `case $line[1] in` blocks. For each `(subcommand)` label, extract `_arguments` lines. Parse each line with regex patterns:

| Pattern | Example |
|---------|---------|
| Value flag + enum | `'--color=[Desc]:COLOR:((auto\:"..." always\:"..."))'` |
| Value flag | `'--threads=[Desc]:THREADS:_default'` |
| Boolean flag | `'--broadcast[Broadcasts the transactions]'` |
| File path | `'--dump=[Desc]:PATH:_files'` |
| Dir path | `'-C+[Desc]:PATH:_files -/'` |

Key prefixes: `*` = repeatable, `(--other)` = conflicts-with, `+` after short flag = takes value, `=` after long flag = takes value.

**Pass 3 — Merge short/long pairs:** Group flags sharing identical description text. Longest `--` form becomes `name`, `-x` form becomes `short`, other `--` forms become `aliases`.

**Edge cases:**
- Multi-line enum values (join `\` continuation lines first)
- Shell-escaped quotes (`'\''` → `'`, `\:` → `:`)
- Duplicate alias blocks (`(t)` duplicates `(test)`) — skip using alias map from Pass 1

## Step 3: Generate Output Files

The script writes `src/lib/forgeCompletions.ts` and `src/lib/castCompletions.ts`:

```typescript
import type { CliCompletionRegistry } from "./completionTypes";

export const forgeRegistry: CliCompletionRegistry = {
  tool: "forge",
  globalOptions: [...],
  subcommands: [...]
};
```

Generated files are **committed to repo** (not gitignored) so Crucible works without Foundry at build time. Regenerate manually when Foundry updates.

## Step 4: Add Script to package.json

```json
{ "scripts": { "generate:completions": "bun run scripts/generate-completions.ts" } }
```

## Verification

After running `bun run scripts/generate-completions.ts`:
- `forge` registry should have ~30+ top-level subcommands
- `forge test` / `forge script` should each have 80+ options
- `cast` registry should have 60+ top-level subcommands
- Every `valueType: "enum"` option has at least one `enumValues` entry
- No parse errors logged to stderr
- Generated files pass `bun run tsc --noEmit` (if tsconfig exists)
- Spot-check: `forgeRegistry.subcommands.find(s => s.name === "script")?.options` includes `--broadcast`, `--verify`, `--rpc-url`, `--sender`
